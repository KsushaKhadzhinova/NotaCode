# Контекст диалога: решения и пожелания автора (23.09.2026)

Журнал решений и требований автора проекта, зафиксированных в рабочем диалоге. Документ предназначен для передачи контекста последующим исполнителям и агентам.

## Назначение проекта

- Проект используется в курсовой работе (ИТиВП, ч.2), в дисциплине ИИТ (коммерциализация, версия Pro) и в лабораторных работах ИТиВП.
- Назначение: собственный язык описания диаграмм; ручное построение BPMN и аналогичных нотаций трудоёмко, специализированные инструменты ограничены.

## Решения автора

1. Проект начинается с нуля: новая папка `E:\NotaCode`, новый репозиторий. В предыдущих версиях зафиксированы грубые ошибки и потеря функционала между версиями. Старые папки — только справочник.
2. Архитектура — enterprise, распределённая, по книгам O'Reilly о распределённых системах, по «Чистому коду» и «Чистой архитектуре». Выбор стека делает ассистент как архитектор, с обоснованием. От стека лаб можно отходить, если это обосновано.
3. AI сейчас — заглушка плюс инструкции по получению ключа у каждого провайдера. Используются бесплатные ключи. Генерация по изображению планируется, но делается после проектирования MVP.
4. Нотации — все типы и подтипы, в системе явно разделены (нотация → тип → уровень). Для сетей Петри: обычные, раскрашенные и нераскрашенные, временные, стохастические, ингибиторные, объектно-ориентированные.
5. Макеты — это мудборды. Визуальный ориентир: VS Code для кода и работы в IDE, draw.io для диаграмм и работы с ними. Не придумывать свой UI.
6. Интерфейс: настоящие светлая и тёмная темы; менее «ИИ-шный» вид; небольшие скругления; двигаются размеры окон и выпадающих списков; все кнопки работают.
7. Обязательные элементы UI:
   - Боковая панель:
     - шаблоны (вставляются в свой файл, сам шаблон не редактируется, есть копирование в буфер);
     - поиск файлов;
     - отладка;
     - терминал;
     - статус;
     - расширения;
     - профиль.
   - Нижняя панель: вкладки Terminal и Problems.
   - Тосты Error/Warning/OK.
   - Кнопки:
     - Run (рендер только по нажатию, автообновление — опция);
     - Save;
     - Export;
     - Import;
     - AI;
     - Документация (?).
   - Статус-бар:
     - ошибки и предупреждения;
     - куда пушим;
     - язык;
     - Ln/Col;
     - Spaces;
     - язык приложения;
     - уведомления;
     - кодировка;
     - время последнего сохранения и пуша.
   - Сверху: имя файла и путь.
   - Подсветка «элемент ↔ строки кода».
   - Масштаб и перемещение холста.
   - Автосохранение выполняется в место и формат последнего сохранения; при отсутствии последнего сохранения запрашиваются место, формат и имя.
   - История версий, откат, diff двух версий.
   - Undo/redo.
   - Валидация и автоисправление.
8. Сохранение: БД (аккаунт), устройство, GitHub API, Google Drive API. Экспорт: SVG, PNG, формат нотации, расширения кода и проекта.
9. Движки и интеграции: PlantUML, Mermaid, Graphviz DOT, D2, Kroki, Text2Diagram, AI-Diagram, draw.io, Gleek, BPMN XML/XMI — «по максимуму».
10. Качество: 100% покрытие тестами для всех лаб, **ноль комментариев в коде**, Clean Code.
11. Не добавлять функции «ради добавления». Дополнительные функции оформляются как предложения с приоритетом и включаются после утверждения автором.
12. Скиллы и агенты специалистов (около 60 ролей) и технологические скиллы — в `E:\NotaCode\.claude\`.
13. Ближайшие задачи: полная документация бизнес- и системного аналитика, все диаграммы, тестовая документация, диаграмма Ганта, приоритизация и границы MVP, ревью архитектуры, граф знаний по проекту, затем лабы 1 и 2.
